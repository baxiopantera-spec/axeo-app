# Daily manual passwords — secure backend

Эта версия делает ежедневную ротацию паролей через сервер. Пароли и содержимое мануалов не хранятся в `index.html`.

## Как это работает

1. Для каждого конечного мануала сервер рассчитывает отдельный пароль на текущий день. Пароль является псевдослучайным HMAC-значением от секретного ключа сервера, даты и идентификатора мануала.
2. В мини-апе пароль проверяется через `POST /api/manual/verify`. Правильный пароль выдаёт короткоживущий токен доступа.
3. Сам HTML мануала загружается только после проверки токена через `GET /api/manual/content`.
4. Telegram-бот показывает сотруднику актуальный пароль по кнопке. Сообщение с паролем автоматически удаляется через заданное число секунд.
5. Бот разрешает выдачу паролей только Telegram ID из `ALLOWED_TELEGRAM_IDS` и только в личном чате.

## Установка

Нужен отдельный Node.js сервер с HTTPS-доступом из мини-аппа.

```bash
npm install
cp .env.example .env
# заполни .env
npm start
```

В `frontend/index.html` замени:

```js
const MANUAL_AUTH_API = "https://YOUR-AUTH-BACKEND.example.com";
```

на фактический HTTPS URL сервера.

## Telegram

Создай отдельного бота через BotFather и положи токен только в `BOT_TOKEN`. Telegram Bot API поддерживает получение обновлений через `getUpdates`; webhook и long polling взаимоисключающие. Эта сборка использует long polling.

Узнать свой Telegram ID можно командой `/id`. Затем добавь ID в `ALLOWED_TELEGRAM_IDS`. Для выдачи паролей в группах бот откажется и попросит использовать личный чат.

## Важный момент

Если оставить содержимое мануалов внутри `index.html`, пароль будет только UI-ограничением: технически содержимое можно найти в исходном JS. Поэтому для реальной защиты персонала содержимое перенесено в `manuals.json` на backend.
